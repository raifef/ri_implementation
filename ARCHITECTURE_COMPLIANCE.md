# Architecture Compliance and Scientific Boundaries

## External scalability contrast

`hdfa_rl_suite.evaluation.scalability` implements a provenance-separated contrast with
Sivak *et al.* (Nature 655, 879–884, 2026): published Figure-5/Supplement-VI anchors,
declared factor-graph and tracking surrogates, structural resource counts through d=15,
and optional executions of the actual suite controller paths. Stage 6 identity covariance,
sampling, masked losses and covariance updates now retain graph-sparse storage and bounded
local factorization rather than introducing hidden global O(P²)/O(P³) paths. Regional MPC
instances and forecast scenarios receive only their owned one-hop controls; the global
merge remains the atomic safety boundary. Repeated scenario likelihoods use a numerically
equivalent NumPy kernel checked against the scalar reference, while independent paired-seed
pipeline conditions can run in bounded spawned workers with canonical result ordering,
atomic per-condition checkpoints and pool-resizing resume. Wall time is measured outside
allocation tracing and absolute/baseline-subtracted process resident memory is sampled
independently, with one fresh process per parallel condition to isolate retained allocator state.

## Deliberate external boundaries

The repository now contains the complete simulator/reference implementation and extension interfaces, but the following cannot honestly be declared *empirically achieved* without resources not present in the project:

- QPU-specific pulse compiler feasibility, analog transfer functions, leakage measurement, hardware interlocks, atomic controller upload/acknowledgement, FPGA/event-bus deployment and distributed GPU acceleration.
- Real-QPU validation of the declared control-error-to-circuit-noise map. The repository now provides named Stim/PyMatching circuit-level logical evidence, while the original generic proxy remains separately labelled.
- Real-device posterior coverage, sim-to-real validity, and measured 10×/5×/2× performance. The benchmark gates report these as falsifiable results.
- Formal proof in a theorem prover. The deterministic invariant kernel and property/fault tests are the executable reference to be translated into a chosen formal tool.

These are backend/experimental certification tasks, not silent software TODOs. A hardware adapter must implement the existing backend, acknowledgement, nonlinear-validation, and supervisor health interfaces; it cannot bypass them.
